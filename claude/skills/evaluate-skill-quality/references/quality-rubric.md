# Skill 质量评分细则

## 目录

- 使用规则
- 评分维度
- 严重度、扣分参考与等级
- 八个维度检查要点

## 使用规则

- 总分 100 分，逐维度给分后相加。
- 先记录事实，再判断问题；扫描告警不能直接扣分。
- 同一根因只在主要维度扣一次。
- 简单 Skill 不因流程短、没有脚本或没有 eval 自动扣分；只有与其风险和复杂度不匹配时才扣分。
- 无法取得证据时标记“未评估”，报告不得表现出虚假精确性。

## 评分维度

| 维度 | 分值 | 满分标准 |
|---|---:|---|
| 目标与触发 | 10 | 做什么、何时用、何时不用清晰，名称与描述可路由 |
| 输入输出契约 | 15 | 必需输入、默认值、前置条件、输出格式和完成定义明确 |
| 自由度与流程 | 15 | 风险与自由度匹配，决策点、质量门、重试与停止条件清晰 |
| 渐进式披露 | 10 | 正文精简，高频闭环，低频资料按需加载，无明显重复 |
| 资源与依赖 | 15 | scripts/references/assets 职责合理，直接依赖契约清晰可达 |
| 验证与评测 | 15 | 有与风险相称的静态验证、真实案例、回归或基线比较 |
| 安全与副作用 | 10 | 写入范围、危险动作确认、只读边界和失败策略明确 |
| 路径与运行时 | 10 | 路径可移植，环境假设明确，源码/安装版/依赖无关键漂移 |

## 严重度

| 级别 | 判定 | 常见影响 |
|---|---|---|
| P0 | 已构成破坏性、安全或未经授权行为，或核心产物必然错误 | 数据破坏、越权、敏感信息泄漏 |
| P1 | 核心路径在现实输入下可能稳定失败、写错目标或无法收敛 | 主流程不可用、错误目录写入、依赖契约断裂 |
| P2 | 特定分支失败、结果明显漂移、验证不足或维护成本较高 | 偶发错误、错误结论、回归风险 |
| P3 | 轻微可维护性、表达、交互或上下文经济性问题 | 冗余、确认疲劳、低价值 token 消耗 |

## 扣分参考

- P0：相关维度记 0；总体建议“不建议直接使用”。
- P1：相关维度通常扣 5～该维度全部分值；必须影响使用建议。
- P2：相关维度通常扣 2～4 分。
- P3：相关维度通常扣 1 分。
- 多个问题共享根因时合并，不累计惩罚。
- 评分是证据摘要，不以分数替代问题解释。

## 等级与建议

| 分数 | 等级 | 默认建议 |
|---:|---|---|
| 90～100 | A | 可稳定使用 |
| 75～89 | B | 修复主要问题后稳定使用 |
| 60～74 | C | 关键契约或验证不足，不建议直接用于高风险任务 |
| 0～59 | D | 不建议直接使用 |

存在 P0 时无论分数多少均为 D。存在阻塞核心路径的 P1 时，最高建议为“修复后使用”。

## 各维度检查要点

### 目标与触发

- description 是否同时包含能力和触发上下文。
- 手动 Skill 是否有清晰 argument-hint；自动 Skill 是否有近似反例边界。
- 名称、目录名、标题和实际职责是否一致。
- 是否错误吞并相邻 Skill 的职责。

### 输入输出契约

- 缺失、非法、冲突输入如何处理。
- 隐含变量（当前工程、默认分支、输出目录）是否可解析。
- 输出是否有固定结构、位置和消费者。
- 成功、暂停、失败、阻塞和完成条件是否明确。

### 自由度与流程

- 高风险、不可逆、易错步骤是否低自由度。
- 探索、分析和表达是否保留必要判断空间。
- 强制规则是否解释目的，是否存在重复或互相冲突。
- 重试是否有范围、增量策略和停止条件。

### 渐进式披露

- 同时检查行数、预估 token、信息密度和高频路径。
- 超过 500 行是复核信号，不是自动缺陷。
- 高频核心步骤不应被拆得需要多次跳转。
- 低频变体、长 Schema 和平台差异应下沉 reference。
- scripts 不按正文上下文长度扣分。

### 资源与依赖

- 重复机械逻辑是否脚本化。
- reference 是否从 SKILL.md 可发现，且读取条件明确。
- 调用方使用的结构化字段是否由被调用方保证。
- 依赖缺失、同名冲突、源码与安装版不一致是否影响当前运行。

### 验证与评测

- 格式校验不能代替真实任务验证。
- 客观输出优先使用断言；主观输出使用用户评价或盲评。
- 复杂 Skill 是否有典型、边界和失败案例。
- 验证是否泄露预期答案或修改意图。

### 安全与副作用

- 只读 Skill 是否明确禁止写入和执行目标逻辑。
- 写入路径是否限定在解析后的安全根目录。
- 发布、删除、数据库写入和外部发送是否有确认门。
- allowed-tools 较宽时，正文是否仍声明行为边界。

### 路径与运行时

- 避免引号内 `~`、固定用户名路径和依赖当前工作目录的模糊相对路径。
- 使用 Skill 自带资源时优先 `${CLAUDE_SKILL_DIR}` 或等价机制。
- 区分仓库源码、安装副本和符号链接。
- 运行时检查只读，不得自动同步或覆盖安装目录。
